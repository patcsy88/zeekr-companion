# Security review: Second factor on the owner login (ADR-013)

Date: 2026-11-06. Scope: the uncommitted ADR-013 working tree (migration `0016`, `totp.py`, `repositories/owner_mfa.py`, `services/auth.py`, `cli/set_mfa.py`, schema, web sign-in, docs). Reviewer: Security Engineer (self-review by the building team; no outside reviewer). Method: code read end to end, then the test suite. Timing statements come from reading the code, not from measurement. No real authenticator app was used.

## Verdict

No Critical or High finding. The second factor is checked on every login that reaches the check, a wrong, missing or reused code gives the same `401` as a wrong password, a code is spent only when the whole login is otherwise right, and nothing secret is logged or returned. Open items are Low or Info, plus three things only the owner can prove after deploy.

## Findings

| Id     | Severity | Location                                   | Description                                                                                                                                                                                                                                                                                                                                                          | Recommendation                                                                                         | Status                              |
| ------ | -------- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------- |
| SEC-M1 | Low      | `models.py` `OwnerMfa.secret`              | The TOTP secret is stored in plain text in the database (owner decision, ADR-013 answer 1). Anyone who reads the database or an unencrypted export can generate valid codes. The export is encrypted at rest.                                                                                                                                                        | Keep exports encrypted. Encrypting the column would need the `cryptography` package, a new dependency. | Accepted (owner, 2026-11-06)        |
| SEC-M2 | Low      | `services/auth.py`                         | A stolen, unexpired one-hour token is not stopped by the second factor. Turning MFA on or off does not revoke tokens already issued.                                                                                                                                                                                                                                 | Rotate `TOKEN_SECRET` and restart to end sessions at once. The command prints this.                    | Accepted, as in ADR-006 SEC-L2      |
| SEC-M3 | Low      | `services/rate_limit.py` (unchanged)       | The login limiter is in memory and per process. A wrong code counts as a failure, so a 6-digit code (about 1 in 333,000 per guess with three accepted steps) is covered by the same 5-in-15-minutes per-client and 20 global limits. A restart clears the counters.                                                                                                  | None needed for one owner.                                                                             | Accepted                            |
| SEC-M4 | Low      | `repositories/owner_mfa.py` `use_recovery` | A recovery code is removed with a compare-and-set on the whole hash list. Two parallel requests with the same code: one wins, the other gets 401. Tested at the repository level (`accept_step`); the recovery path uses the same pattern.                                                                                                                           | None.                                                                                                  | Verified by reading, partly by test |
| SEC-M5 | Info     | `totp.py` `match_step`                     | All steps in the window are compared with `hmac.compare_digest`, so timing does not show which matched. Malformed codes return early (length, digits only); that reveals only the format rules.                                                                                                                                                                      | None.                                                                                                  | Verified                            |
| SEC-M6 | Info     | `services/auth.py` `login`                 | The factor check runs whether or not the password was right, so a wrong password costs the same second-factor work. `_spend` runs only after the password, username and factor are all right, so a wrong password never burns a valid code. A recovery code costs up to 8 scrypt checks at `N=2**14`; they are not behind the semaphore that caps the password hash. | A burst of recovery-looking codes is limited by the login limiter. Revisit if the limiter changes.     | Accepted                            |
| SEC-M7 | Info     | `cli/set_mfa.py`                           | The command prints the QR, the secret and the recovery codes to the terminal. If the terminal is logged (for example `script`, a tmux log, or a pasted screenshot) they are exposed. Saving happens only after a live code is confirmed, so an abandoned run changes nothing.                                                                                        | Docs tell the owner to use a private terminal and not paste the output.                                | Documented                          |
| SEC-M8 | Info     | `models.py`                                | `repr=False` is not available on mapped columns here, so `OwnerMfa.secret` would show in a repr of the object. No code logs or prints the row.                                                                                                                                                                                                                       | Do not log the object. A test checks that failed logins log neither code nor secret.                   | Accepted                            |

## Checked and clean

| Area                                                                       | Evidence                                                                                                              |
| -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| TOTP maths                                                                 | All six RFC 6238 SHA-1 vectors (`tests/test_totp.py`)                                                                 |
| Drift limited to one step either side                                      | `test_one_step_of_clock_drift_is_accepted`, `test_more_than_one_step_of_drift_is_refused`                             |
| Replay refused                                                             | `test_a_code_works_only_once`, `test_an_older_code_is_refused_after_a_newer_one_is_used`; atomic update `accept_step` |
| Same 401 body for wrong password, wrong code, missing code                 | `test_missing_or_wrong_code_is_the_same_401_as_a_wrong_password`                                                      |
| Wrong password does not spend a code                                       | `test_a_right_code_with_a_wrong_password_is_refused_and_not_spent`, and the recovery equivalent                       |
| Wrong and missing codes count toward lockout                               | `test_wrong_codes_count_toward_the_lockout`, `test_a_missing_code_counts_toward_the_lockout`                          |
| MFA off changes nothing; a supplied code is ignored                        | `test_without_mfa_*`                                                                                                  |
| Nothing logged or returned                                                 | `test_failed_attempts_log_neither_the_code_nor_the_secret`, `test_the_response_never_contains_mfa_material`           |
| Recovery codes stored hashed, once only                                    | `test_recovery_codes_are_stored_hashed`, `test_a_recovery_code_signs_in_once`                                         |
| Setup saves nothing until a live code is confirmed; cancel changes nothing | `test_set_mfa_saves_nothing_if_the_code_is_never_right`, `test_set_mfa_cancelled_changes_nothing`                     |
| The otpauth link is not printed, only drawn as a QR                        | `test_set_mfa_saves_only_after_a_right_code`                                                                          |
| No endpoint changes MFA                                                    | `routers/auth.py` has only `POST /token`                                                                              |
| Migration constraints and downgrade                                        | `test_0016_owner_mfa_checks_and_downgrade`                                                                            |
| Dependency                                                                 | `segno==1.6.6`, `pip-audit`: no known vulnerabilities                                                                 |

## Not verified (owner to prove after deploy)

- That Google Authenticator accepts the generated `otpauth://` link and its codes match the server's.
- That the terminal QR scans in the owner's terminal; the printed key is the fallback.
- The host clock accuracy. Check `timedatectl` on the host. A clock off by more than about 30 seconds makes valid codes fail.
- A real sign-in from the phone with MFA on.
